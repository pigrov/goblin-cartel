# Итерация 0051: специализации сборщиков и первые инструменты контента в админке

## Цель

Сделать следующий шаг в механике гоблинов: сборщик должен быть не просто свободным слотом автосбора, а конкретным гоблином со специализацией и понятным выбором для шахты. Параллельно начать переносить работу с гоблинами, рудниками и типами шахт в UI админки, не ломая текущий JSON draft/publish flow.

## Сделано

- В content schema добавлено поле `specialization` для гоблинов и первые эффекты постоянных шахт: `mine_capacity_multiplier`, `mine_production_multiplier`, `build_time_multiplier`.
- Стартовый сборщик `Пип Сухая Книга` получил специализацию `Кладовщик` и бонус вместимости назначенной шахты.
- Добавлен второй стартовый сборщик `Нокк Медное Перо` как `Рудный эксперт` с бонусом добычи медной руды.
- Выбор сборщика для постоянной шахты переведен в отдельную модалку: видно специализацию, занятые/доступные слоты и эффекты гоблина.
- Клиентский слой шахт учитывает бонусы назначенного сборщика при видимом производстве, вместимости и ручном/автоматическом сборе, не перезаписывая базовые параметры шахты.
- Runtime content теперь дозаполняет недостающих стартовых гоблинов и новые starter-эффекты для старых опубликованных версий контента.
- Логика слотов и бонусов сборщиков вынесена в `builtMineClientState` и покрыта unit-тестами.
- В админке на экране `Content` добавлен первый entity UI поверх текущего JSON draft: счетчики сущностей, последние гоблины/рудники/типы шахт и кнопки создания шаблонов `Гоблин`, `Рудник`, `Тип шахты`.
- Кнопки админки создают валидируемые черновые записи в текущем JSON, после чего работают штатные `Save`, `Validate`, `Publish`.

## Открытые вопросы

- Нужно решить прогрессию слотов сборщиков по уровням и где будет жить хижина/улучшение лимитов.
- Следующий слой админки лучше делать уже entity-level: отдельные формы редактирования гоблина, рудника, жилы и типа шахты вместо генерации шаблонов в JSON.
- Нужно добавить боевые/рейдерские типы гоблинов, когда появится механика захвата и событий.
