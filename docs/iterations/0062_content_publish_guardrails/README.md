# 0062 content publish guardrails

## Цель

Дочистить старые пути редактирования контента после перехода рудников на `cellMap`: убрать тихие fallback-данные из игры, убрать тестовую runtime-глубину и закрыть прямое сохранение полного JSON из обычного UI админки.

## Сделано

- Game client больше не подставляет starter content при ошибке `/api/content/current`; вместо этого показывает ошибку загрузки контента.
- Runtime-подмена первой шахты до 10 метров и `debugMineRows` удалены, клиент использует опубликованные размеры рудника как есть.
- Fallback-поиск ресурсов, гоблинов, жил, сундуков и типов шахт из `starterContentBundle` удален из игрового UI.
- JSON в админке оставлен как read-only диагностический просмотр; кнопка сохранения полного JSON удалена из экрана версии.
- Кнопки создания шаблонов в админке теперь сохраняют новую сущность через entity endpoint и серверную валидацию.
- `validateContentBundle` проверяет локализацию на replacement char, типичные mojibake-маркеры и длинные серии вопросительных знаков.
- `encoding:check` дополнительно ловит длинные серии вопросительных знаков в текстовых файлах, кроме явно помеченных тестовых fixture.
- Добавлены unit-тесты на отсутствие legacy-полей в starter content и на отказ от битой локализации.

## Контекст

Опубликованный content `0.0.8` в production оказался структурно чистым, но локализация в БД была повреждена сериями вопросительных знаков. Эта итерация закрывает путь, при котором такая версия может пройти validate/publish незамеченной.
