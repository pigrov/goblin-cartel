# Goblin Cartel: игровые системы и экономика

**Версия:** 0.1  
**Дата:** 2026-04-28

## 1. Базовый цикл

```text
Рудник → блоки → ресурсы → жила → строительство шахты → периодический доход → автоматизация → укрупнение производства → новый рудник
```

Цель системы — дать игроку простое действие и постепенное ощущение промышленного роста.

## 2. Рудник

Рудник — это вертикальная сетка блоков.

Рекомендация для MVP:

```text
width = 8
height = 12-14
visibleRows = 7
```

Каждый блок имеет:

| Параметр | Описание |
|---|---|
| `blockTypeId` | тип блока |
| `hp` | текущая прочность |
| `maxHp` | максимальная прочность |
| `rewardTableId` | таблица наград |
| `state` | целый / трещины / почти сломан / разрушен |
| `special` | сундук, жила, взрыв, none |

## 3. Прочность блоков

Базовая формула:

```text
blockHp = baseHp(blockType) × depthMultiplier × mineDifficultyMultiplier
```

Пример множителей:

| Материал | baseHp |
|---|---:|
| Земля | 20 |
| Камень | 60 |
| Твёрдый камень | 150 |
| Медная руда | 120 |
| Железная руда | 260 |
| Золото | 180 |
| Хлам | 100 |
| Кристалл | 500 |

Множитель глубины:

```text
depthMultiplier = 1 + floor(rowIndex / 5) × 0.25
```

Это мягко повышает сложность без резкого удара по игроку. Удар по игроку в idle должен быть экономическим, а не психологическим.

## 4. Урон по блокам

### 4.1. Урон гоблина

```text
goblinDps = strength × speed × classMultiplier × toolMultiplier × blockTagBonus
```

Где:

- `strength` — сила;
- `speed` — ударов в секунду;
- `classMultiplier` — бонус класса;
- `toolMultiplier` — бонус экипировки;
- `blockTagBonus` — бонус по типу блока.

### 4.2. Урон бригады

```text
teamDps = sum(activeGoblinDps) × foremanMultiplier × automationMultiplier
```

### 4.3. Удар босса

Игрок тратит энергию:

```text
bossHitDamage = baseBossDamage × bossLevelMultiplier × comboMultiplier
```

Рекомендация:

- энергия копится со временем и офлайн;
- один удар тратит 10 энергии;
- энергия максимум 100 на старте;
- активная игра ускоряет прогресс, но не обязательна бесконечно.

## 5. Энергия босса

Энергия нужна, чтобы тапание было полезным, но не превращало игру в тренажёр для пальца.

MVP-параметры:

| Параметр | Значение |
|---|---:|
| Максимум энергии | 100 |
| Восстановление | 1 энергия / 20 сек |
| Стоимость удара | 10 |
| Урон удара | 100-150 на старте |
| Офлайн-накопление | да, до лимита |

Позже:

- комбо;
- критические удары;
- временные усилители;
- артефакты босса.

## 6. Награды за блоки

Награда задаётся таблицей.

Пример:

| Блок | Награда |
|---|---|
| Земля | 1-3 камня, 5% шанс золота |
| Камень | 3-8 камня |
| Медная руда | 4-12 медной руды |
| Железная руда | 3-8 железной руды |
| Золото | 20-80 золота |
| Хлам | 2-6 хлама |
| Сундук | roll из сундука |

## 7. Жилы

Жила — особая находка, которая позволяет построить постоянную шахту.

Типы MVP:

| Жила | Постройка |
|---|---|
| Золотая жила | малая золотая шахта |
| Каменный пласт | каменоломня |
| Медная жила | малая медная шахта |
| Железная жила | малая железная шахта |

Важное правило:

> Найденная жила не просто даёт ресурс, а открывает объект постоянного дохода.

## 8. Строительство шахт

Когда жила найдена, игрок может построить шахту.

Пример:

```text
Малая медная шахта
Стоимость: 500 золота, 120 камня
Время: 60 секунд
Требование: 1 строитель
Производство: 120 медной руды / час
Хранилище: 300
```

## 9. Доход шахт

Шахта производит ресурс в собственное хранилище.

Формула:

```text
produced = productionPerHour × elapsedHours × mineLevelMultiplier × automationMultiplier
```

Если хранилище заполнено, производство останавливается:

```text
stored = min(capacity, stored + produced)
```

Это создаёт причину для сбора и автоматизации.

## 10. Ручной сбор

На старте игрок сам собирает доход.

Цель не в том, чтобы мучить игрока, а чтобы он почувствовал ценность авто-сбора. Тонкая грань, которую мобильные игры регулярно переезжают катком.

Рекомендация:

- первая шахта: ручной сбор;
- после 2-3 шахт: открыть собирателя;
- после 5+ шахт: открыть вагонетки;
- после 10 шахт: открыть объединение.

## 11. Автоматизация

Автоматизация — главный путь прогрессии.

### 11.1. Узлы MVP

| Узел | Эффект |
|---|---|
| Старший шахтёр | авто-выбор следующего блока |
| Собиратель | авто-сбор с одной шахты |
| Вагонетка | ускоренный сбор, больше вместимость |
| Бригадир | управление несколькими шахтёрами, меньше простоев |
| Буровая стойка | пассивный урон по колонке |
| Шахтный участок | объединение 10 одинаковых шахт |

### 11.2. Принцип цены

Автоматизация должна быть дорогой, но достижимой.

Правило:

```text
игрок должен 2-4 раза почувствовать ручную боль, а потом получить инструмент, который её убирает
```

Если ждать дольше — игрок злится. Если дать сразу — игрок не ценит.

## 12. Объединение шахт

Система укрупнения:

```text
10 малых шахт → 1 рудный участок
10 участков → 1 шахт-завод
10 шахт-заводов → 1 промышленный район
```

### 12.1. Зачем объединять

- уменьшить количество объектов в UI;
- дать чувство масштаба;
- открыть новые бонусы;
- встроить авто-сбор;
- подготовить карту территорий.

### 12.2. Пример

```text
10 малых медных шахт
↓
Медный рудный участок Lv. 1
Доход: сумма шахт × 1.15
Хранилище: сумма × 1.25
Сбор: через вагонетки
```

## 13. Гоблины

### 13.1. Базовые статы

| Стат | Эффект |
|---|---|
| Сила | урон по блокам |
| Скорость | частота ударов / действий |
| Удача | шанс бонусной награды |
| Верность | меньше простоев/потерь, будущие бунты |
| Мастерство | бонус к классовой роли |

### 13.2. Классы

| Класс | Основная формула |
|---|---|
| Шахтёр | урон по блокам |
| Строитель | скорость и цена строительства |
| Собиратель | скорость и объём сбора |
| Инженер | эффективность автоматизации |
| Бригадир | снижение простоев и авто-назначение |

### 13.3. Прокачка

```text
levelCost = baseCost × level^growthExponent
statGain = baseGain × rarityMultiplier
```

Рекомендация для MVP:

- максимум уровня: 20;
- редкости: common, rare, epic;
- без сложной экипировки на старте;
- 1 способность на гоблина.

## 14. Производство

После MVP или ближе к концу MVP открывается плавильня.

### 14.1. Рецепты

| Рецепт | Вход | Выход |
|---|---|---|
| Медные слитки | медная руда | медный слиток |
| Железные слитки | железная руда | железный слиток |
| Детали | хлам | детали |

### 14.2. Для чего нужны переработанные ресурсы

- улучшения кирок;
- вагонетки;
- рельсы;
- буровая стойка;
- апгрейды шахт;
- укрупнение шахт.

## 15. Офлайн-прогресс

### 15.1. Что считается офлайн

- производство шахт;
- сбор, если есть авто-сбор;
- восстановление энергии босса;
- строительство;
- производство в плавильне.

### 15.2. Что не считается офлайн в MVP

- активные удары босса сверх энергии;
- случайные события;
- новые блоки, если нет авто-копания;
- прохождение рудника без соответствующей автоматизации.

### 15.3. Ограничения

MVP:

```text
maxOfflineHours = 8
```

Позже можно увеличить через апгрейды.

## 16. Экономические bottlenecks

На разных этапах должен быть разный “узкий ресурс”.

| Этап | Bottleneck |
|---|---|
| 0-15 минут | золото / камень |
| 15-30 минут | медная руда |
| 30-60 минут | место/сбор шахт |
| 60-180 минут | железо / хлам |
| День 1 | автоматизация / объединение |

## 17. Туториальные цели

MVP-задания:

1. Разбей 10 блоков.
2. Найми второго шахтёра.
3. Найди медную жилу.
4. Построй малую медную шахту.
5. Собери доход с шахты.
6. Улучши шахту до 2 уровня.
7. Назначь собирателя.
8. Открой железный рудник.
9. Купи вагонетку.
10. Объедини 10 шахт в участок.

## 18. Метрики баланса

Для каждого рудника нужно считать:

- среднее время прохождения;
- блоков разрушено вручную;
- блоков разрушено гоблинами;
- ресурс в час;
- время до первой шахты;
- время до первой автоматизации;
- количество ручных сборов до авто-сбора;
- количество возвратов игрока после офлайна.

## 19. Главная дизайн-формула

```text
Новая механика должна либо:
1. открыть новый ресурс,
2. убрать ручное действие,
3. ускорить видимый прогресс,
4. дать новый тип объекта,
5. подготовить будущую систему.
```

Если механика не делает ничего из этого, она, скорее всего, просто украшает таблицу. А таблицы и так слишком уверены в себе.
