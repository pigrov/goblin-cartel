## Что внутри

Этот комплект документов фиксирует текущую концепцию игры и превращает разговорную идею в рабочую основу для разработки. Не священное писание, к счастью, а стартовый набор документов, который можно менять по мере прототипирования.

## Ключевые решения, уже зафиксированные

1. Игра стартует не с PvP, захватов и угроз, а с понятного ядра: **копать → находить жилы → строить шахты → автоматизировать → укрупнять производство**.
2. Первый клиент: **Vite + React + PixiJS**, Android-обёртка через **Capacitor**.
3. Продукт должен существовать в трёх формах:
   - **Android-приложение** для RuStore;
   - **web-версия** для тестирования, демо и возможной публикации;
   - **админка** для настройки контента, генерации уровней, баланса и LiveOps.
4. Админка не является “приятным бонусом на потом”. Для idle-игры она нужна рано, иначе баланс и уровни будут правиться руками в коде, то есть разработчики добровольно выберут археологию боли.
5. MVP не должен включать полноценные клановые войны, PvP и сложные LiveOps. Эти системы строятся поверх шахтно-автоматизационного ядра.
6. Для БД используется **PostgreSQL + Drizzle + drizzle-kit**; миграции обязательны и коммитятся.
7. Документация каждой итерации ведётся в `docs/iterations/NNNN_name_iteration`.
8. Общий UI-стиль берётся из `08_ui_ux_style_guide.md` и фиксируется в общем файле темы при появлении frontend-кода.
9. Unit tests, UTF-8 check и проверка битых символов являются обязательной частью итерации.
10. Секреты приложения, кроме базовых runtime-переменных, настраиваются в админке и хранятся зашифрованными в БД через `APP_CREDENTIALS_MASTER_KEY`.

## Рекомендуемый порядок использования документов

1. Прочитать `01_game_concept.md` и согласовать направление.
2. По `02_mvp_and_roadmap.md` зафиксировать MVP без расползания объёма.
3. По `03_stack_architecture.md` поднять репозиторий и базовый проект.
4. По `04_admin_cms_and_generation.md` определить минимальную админку и формат конфигов.
5. По `05_game_systems_economy.md` реализовать первый рабочий цикл.
6. По `06_rustore_release_plan.md` заранее убрать риски публикации.
7. По `09_sample_configs.md` начать делать первые JSON/YAML-конфиги.
8. По `10_development_rules.md` вести каждую итерацию, проверки и технические решения.
