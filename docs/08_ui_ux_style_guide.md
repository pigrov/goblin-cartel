# Goblin Cartel: UI/UX и визуальный стайлгайд

**Версия:** 0.1  
**Дата:** 2026-04-28

## 1. Цель UI

UI должен быть:

- понятным на маленьком экране;
- достаточно “игровым”, а не таблицей;
- тёмным, подземным, но читаемым;
- пригодным для генерации ассетов;
- простым для реализации в React + PixiJS;
- без сложной 3D-анимации.

## 2. Визуальное направление

```text
dirty cartoon dark fantasy industrial UI
```

Ключевые материалы:

- дерево;
- камень;
- медь;
- железо;
- ржавчина;
- грязь;
- свечи/факелы;
- руны/царапины;
- мешки, ящики, вагонетки.

Настроение:

- смешное;
- грубое;
- жадное;
- подземное;
- но не хоррор.

## 3. Цветовая система

| Назначение | Цветовой диапазон |
|---|---|
| Основной фон | тёмно-коричневый / почти чёрный |
| Панели | дерево, тёмная бронза |
| Основной акцент | золото / жёлтый |
| Опасность | красно-оранжевый |
| Энергия | голубой / бирюзовый |
| Успех | зелёный |
| Заблокировано | серо-коричневый |
| Медь | оранжево-коричневый |
| Железо | холодный серый |
| Хлам | грязный серый + жёлтые детали |

## 4. Типографика

### Требования

- крупные цифры ресурсов;
- короткие подписи;
- минимум мелкого текста на главном экране;
- длинные описания только в карточках/окнах;
- кнопки минимум 44-48 px по высоте в web terms.

### Тон текста

- коротко;
- с юмором;
- без перегруза;
- не слишком “криминально”, особенно для RuStore.

Пример:

```text
Найдена медная жила!
Гоблины делают вид, что это было по плану.
```

### 5.2. Верхняя панель ресурсов

Показывать максимум 4-5 ресурсов одновременно.

MVP:

- золото;
- камень;
- медь/железо по контексту;
- энергия босса.

Не надо пихать туда 12 валют. Это не финансовый терминал гоблинского банка, хотя они бы пытались.

### 5.3. Сетка шахты

Рекомендация:

```text
8 колонок
блок 42-52 px на типовом телефоне
видимая зона 7 рядов
```

Каждый блок должен быть читаемым по силуэту:

- земля — мягкая форма;
- камень — угловатый серый;
- руда — жилы внутри;
- сундук — узнаваемый ящик;
- жила — крупный яркий знак;
- хлам — металлические куски.

### 5.4. Активный блок

Активный блок имеет:

- обводку;
- HP-bar;
- короткую подпись при наведении/тапе;
- визуальные трещины.

## 11. Анимации

Минимальный список:

| Объект | Анимация |
|---|---|
| Гоблин | 2 кадра удара + idle bounce |
| Блок | оверлей трещин |
| Разрушение | пыль, вспышка, иконки ресурсов |

| Кнопка удара | пульс при полной энергии |
| Вагонетка | движение по рельсам |
| Бур | вращение/тряска |
| Окно награды | появление scale/fade |

## 12. Mobile-first требования

- Portrait orientation.
- Большие кнопки.
- Минимум мелкого текста.
- Скролл только там, где ожидается.
- Ресурсы не должны закрывать шахту.
- Главная кнопка должна быть доступна большим пальцем.
- UI должен учитывать safe area.
- Все важные действия должны быть читаемы на 360×640.

## 13. Web-версия

Web-версия должна:

- адаптироваться под desktop;
- иметь фиксированный mobile canvas preview или responsive layout;
- позволять тестировать геймплей мышью;
- не ломать touch-логику;
- поддерживать debug overlay.

Рекомендация для desktop:

```text
центр: мобильный game frame
справа: debug panel / dev tools only
```

## 14. Debug UI для разработки

В web-dev режиме полезно иметь панель:

- добавить золото;
- добавить энергию;
- открыть следующий рудник;
- разрушить активный блок;
- сгенерировать новый seed;
- показать DPS;
- показать FPS;
- показать текущий contentVersion;
- экспортировать save.

Не выпускать это в production. Удивительно, но пользователи тоже умеют нажимать кнопки.

## 15. Asset guidelines

### 15.1. Гоблины

- full-body или bust portrait;
- крупная голова;
- простые формы;
- 1 основной аксессуар;
- клановый цвет;
- толстая обводка;
- no background для игровых ассетов.

### 15.2. Блоки

- квадратные/слегка неровные;
- 4 состояния разрушения;
- читаемость на малом размере;
- одинаковая перспектива;
- atlas/spritesheet.

### 15.3. UI

- кнопки из дерева/металла;
- золотой акцент для важного;
- красно-оранжевый для действия/энергии;
- серый для заблокированного;
- единая толщина обводки.

## 17. Важное правило UI

Каждый экран должен отвечать на один вопрос:

| Экран | Вопрос |
|---|---|
| Рудник | Что я сейчас ломаю и что получу? |
| Гоблины | Кто работает и кого улучшить? |
| Шахты | Что производит доход и где забрать? |
| Авто | Как убрать ручную рутину? |
| Производство | Во что превратить сырьё? |

Если экран пытается отвечать на пять вопросов сразу, он уже не экран, а совещание. А совещания даже гоблины должны избегать.
