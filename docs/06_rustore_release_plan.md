# Goblin Cartel: план первой публикации в RuStore

**Версия:** 0.1  
**Дата:** 2026-04-28

## 1. Цель документа

Зафиксировать требования и подготовительный чеклист для первой публикации Android-приложения **Goblin Cartel** в RuStore.

Официальные источники RuStore:

- Публикация приложения: https://www.rustore.ru/help/en/developers/publishing-and-verifying-apps/app-publication
- Подписи APK/AAB: https://www.rustore.ru/help/developers/publishing-and-verifying-apps/app-publication/apk-signature
- Требования модерации: https://www.rustore.ru/help/en/developers/publishing-and-verifying-apps/requirement-apps
- Инструменты RuStore: https://www.rustore.ru/developer/en/tools

## 2. Зафиксированная платформа

Первая публикация:

```text
Android-приложение через Capacitor
Площадка: RuStore
Формат загрузки: APK или AAB
```

Рекомендация:

- для ранней публикации проще начать с **APK**;
- для масштабирования и лучшего delivery можно готовить **AAB**, но нужно отдельно учитывать загрузку подписи приложения для AAB.

## 3. Технический pipeline сборки

```text
1. npm run build
2. npx cap sync android
3. Android Studio / Gradle release build
4. Подписание APK/AAB
5. Проверка package name и versionCode
6. Локальный smoke test
7. Загрузка в RuStore Console
8. Заполнение карточки
9. Отправка на модерацию
10. Публикация
```

## 4. Требования к APK/AAB

По официальной документации RuStore:

- RuStore поддерживает APK и AAB.
- APK должен быть подписан цифровым сертификатом.
- Для AAB подпись приложения добавляется отдельно перед загрузкой `.aab`.
- Package name должен быть уникальным.
- Для последующих версий подпись и package name должны совпадать с предыдущими, а `versionCode` должен быть больше предыдущего.
- В документации RuStore указан лимит размера до 5 GB для APK/AAB.

## 5. Package name

Предложение:

```text
com.<studio>.goblincartel
```

Пример:

```text
com.dima.goblincartel
```

Важно: package name нельзя менять после публикации без создания нового приложения. Это тот редкий момент, когда надо подумать заранее, а не героически исправлять потом.

## 6. Android manifest и разрешения

### 6.1. Рекомендация для первой версии

Минимизировать permissions.

Для MVP желательно:

- не запрашивать геолокацию;
- не запрашивать контакты;
- не запрашивать камеру;
- не запрашивать микрофон;
- не запрашивать доступ к файлам, если он не нужен;
- не использовать чувствительные разрешения;
- не использовать запрещённые разрешения.

### 6.2. Почему

RuStore проверяет разрешения. По официальным требованиям, запрещённые permissions могут привести к отклонению версии при загрузке, а sensitive permissions требуют обоснования в консоли.

Для игры про гоблинов, которые долбят камни, камера и контакты не нужны. Если гоблины внезапно захотят контакты пользователя, это уже не игра, а тревожный социальный эксперимент.

## 7. User Data Safety

В RuStore нужно заполнить информацию о категориях и типах данных, к которым приложение получает доступ.

Для первой версии желательно сделать приложение максимально простым:

| Категория | Рекомендация MVP |
|---|---|
| Персональные данные | не собирать без необходимости |
| Аккаунты | не использовать в MVP |
| Платежи | не использовать в первой версии или подключать отдельно |
| Аналитика | если используется, явно описать |
| Сохранения | локальные сохранения, без персональных данных |
| Push | не включать в первой версии без необходимости |

Если будут аналитика, remote config или backend-сохранения, нужно подготовить:

- privacy policy;
- описание собираемых данных;
- основание и цель обработки;
- согласие пользователя, если требуется.

## 8. Возрастной рейтинг

Для Goblin Cartel нужно заранее выбрать возрастное ограничение.

Рекомендация для MVP:

```text
6+ или 12+
```

Зависит от финального визуала и текста:

| Фактор | Влияние |
|---|---|
| Cartoon fantasy violence | может поднять рейтинг |
| Криминальные слова вроде “картель” | лучше подавать как фэнтези/юмор |
| Кровь/жестокость | не использовать в MVP |
| Азартные механики | избегать или оформлять как сундуки без real-money gambling |
| Платежи | требуют прозрачного описания |

Важно: “Goblin Cartel” лучше в описании позиционировать как **фэнтезийную гоблинскую шахтёрскую банду**, а не реалистичный криминал.

## 9. Карточка приложения в RuStore

По документации RuStore при публикации заполняются сведения о приложении: название, категория, возраст, теги, краткое и подробное описание, минимальная версия Android, контакты разработчика, медиа.

### 9.1. Название

Название должно быть коротким. В документации RuStore указан лимит до 30 символов для названия приложения.

Варианты:

- `Goblin Cartel`
- `Goblin Cartel: Mine`
- `Goblin Mines`
- `Гоблинский Картель`

Для первой публикации можно использовать:

```text
Goblin Cartel
```

### 9.2. Краткое описание

До 80 символов.

Варианты:

```text
Копай рудники, нанимай гоблинов и автоматизируй шахты.
```

```text
Idle-игра про гоблинов, шахты, ресурсы и автоматизацию.
```

### 9.3. Подробное описание

Черновик:

```text
Goblin Cartel — это 2D idle-игра про гоблинов-шахтёров. Копайте вертикальные рудники, разбивайте блоки, находите жилы, стройте шахты и превращайте маленькую подземную банду в автоматизированное производство.

Нанимайте гоблинов, улучшайте их силу и скорость, открывайте новые ресурсы, стройте шахты на найденных жилах и запускайте автоматизацию: собирателей, вагонетки, бригадиров и буровые механизмы.

Особенности:
- вертикальные 2D-рудники;
- idle-добыча и активные удары босса;
- гоблины с разными ролями;
- строительство шахт;
- автоматизация производства;
- постепенное открытие новых ресурсов и механизмов.
```

## 10. Медиа для карточки

Нужно подготовить:

| Asset | Что показать |
|---|---|
| Иконка | голова гоблина + кирка/золото |
| Скриншот 1 | главный экран рудника |
| Скриншот 2 | карточки гоблинов |
| Скриншот 3 | экран шахт и дохода |
| Скриншот 4 | автоматизация/вагонетки |
| Скриншот 5 | производство/плавильня, если есть |
| Видео | optional, через VK Video, если решим делать |

## 11. Минимальная версия Android

Capacitor Android официально поддерживает API 24+ и требует Android WebView с Chrome 60+.

Рекомендация:

```text
minSdkVersion: 24
```

Это нужно сверить с выбранной версией Capacitor и требованиями RuStore перед релизом.

## 12. Платежи

Для первой версии можно не включать платежи.

Если платежи нужны:

- использовать RuStore Payments / Pay SDK;
- подготовить описание процесса оплаты;
- подготовить правила возврата/доставки цифровых товаров;
- добавить обработку deeplink/нативных callback, если требуется SDK;
- проверить, как это интегрируется с Capacitor через native plugin/bridge.

Рекомендация:

```text
MVP без платежей. Монетизация после проверки core loop.
```

## 13. Push-уведомления

В первой версии не обязательны.

Если нужны после релиза:

- использовать RuStore tools / push notifications;
- добавить явные настройки согласия/отписки;
- не спамить игрока “твоя медь скучает”, потому что у людей и так уведомлений как у шахты камней.

## 14. Политика конфиденциальности

Даже если MVP почти ничего не собирает, лучше подготовить простую privacy policy.

Минимально описать:

- какие данные собираются;
- где хранятся сохранения;
- используется ли аналитика;
- используются ли push;
- используются ли платежи;
- контакты разработчика;
- как запросить удаление данных, если серверные данные есть.

## 16. Риски публикации

| Риск | Митигировать |
|---|---|
| Лишние permissions | минимальный manifest |
| Неверная подпись | хранить keystore надёжно, не менять между версиями |
| Ошибка versionCode | автоматизировать bump |
| WebView performance | тест на слабых устройствах |
| Непрозрачные данные | privacy policy + User Data Safety |
| Возрастной рейтинг | избегать крови, реалистичного криминала, азартных формулировок |
| Платежи | не включать до готовности RuStore SDK integration |
| Маленькие UI-элементы | мобильный UX-тест до загрузки |

## 17. Что лучше не делать в первой версии

- Не включать real-money платежи, если не готова юридическая/техническая часть.
- Не использовать опасные Android permissions.
- Не делать обязательный интернет.
- Не делать PvP/рейтинги без серверной валидации.
- Не делать “случайные сундуки за деньги”. Это может усложнить рейтинг, правила и доверие.
- Не использовать слово “картель” в реалистичном криминальном смысле в описании. Пусть это будет фэнтезийная гоблинская промышленная шайка, а не симулятор плохой газетной рубрики.
